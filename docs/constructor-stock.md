# Каталог и складской конструктор

Главная и каталог используют `loadPublicBouquets`: только активные записи
`public.bouquets`, строковые ID, реальные цены и фотографии. Корзина общая,
ключ `lotus-cart`. Создание и изменение букета обновляют обе страницы.

Новая композиция сохраняет `schemaVersion: 2`. У экземпляра есть собственный
`id`, складской `flowerId`, `position` и `rotation`. Несколько экземпляров
могут ссылаться на один сорт. Название или тип 3D-модели не определяют складской ID.

`loadConstructorStock` отдаёт активные цветы с продажной ценой и доступным
количеством: физический остаток минус активные резервы, минимум ноль.
Закупочные цены клиенту не передаются. Общий предел — 21 экземпляр.

Новые складские позиции пока не связаны с 3D-моделями. Они сохраняют невидимые
объекты сцены, участвуют в размещении, отталкивании и сборе стеблей, доступны
для выбора и перемещения на карте. Полный состав показан в списке. Неполный
3D-кадр не сохраняется как миниатюра полного букета. Старые v1-композиции
продолжают показывать прежние процедурные модели.

При оформлении сервер заменяет метаданные каждого экземпляра снимком из БД:
название, продажная цена, цвет и фото. Координаты сохраняются после валидации.
Цена — сумма продажных цен экземпляров плюс упаковка. Конфигурация и
динамический состав с ценами сохраняются в существующих `custom_configuration`
и `custom_summary`. Доступность проверяется суммарно для всей корзины с учётом
количества копий букетов. Это не резервирование: подтверждение повторно проверяет
остатки под блокировками. Сборка списывает цветы существующим триггером движений.

Старые корзины v1 сохраняются. Автоматический перевод в v2 допускается только
по однозначной активной связи `constructor_kind → flowerId`. Если связи нет,
редактор сохраняет старый экземпляр и предлагает выбрать складскую позицию.
Без разрешения этой неоднозначности оформление не проходит. Новым композициям
`constructor_kind` не нужен. Старые заказы и суммы не переписываются; активные
резервы старых заказов остаются источником уже выделенных складских позиций.

Миграция не требуется: действующие ограничения JSON-полей допускают v2.

Проверки:

```powershell
node --test scripts/test-public-catalog.mjs scripts/test-customer-phone.mjs scripts/test-checkout-security.mjs
npm run lint
npm run build
git diff --check
```

Тесты БД создают только временные таблицы. Проверка подтверждения и сборки
использует копии действующих триггерных функций в `pg_temp`.

Для браузерной проверки запустить собранное приложение на порту 3107, затем:

```powershell
node scripts/test-constructor-browser.mjs
```

Нужен установленный Chrome (путь можно задать через `CHROME_PATH`) и активный
ассортимент. `LOTUS_TEST_URL` меняет адрес приложения. Тест использует временный
профиль браузера и блокирует запросы публичного оформления и административного API.
